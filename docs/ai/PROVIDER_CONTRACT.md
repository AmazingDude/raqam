## Public interface and approved test seam

Import runtime functions only from `src/lib/ai/index.ts` on the server. `createAIProvider` explicitly selects Gemini with `AI_PROVIDER=gemini`; absent selection retains the Groq default. No credentials-based or error-triggered fallback occurs. Gemini’s environment fields are independently validated, and both providers implement the same three operations. The index, provider and configuration modules all import `server-only`; no SDK client or credential-bearing configuration is exported from the index. B uses A's safe shared domain types instead.

`createGroqProvider(dependencies?)` returns exactly three operations:

- `requestImageExtraction(input, context)`: one already-authorized PNG/JPEG byte array, A's `SourceReference` with null image row, prompt/version IDs and an optional synchronous Zod output schema. It reuses A's upload signature guard and 2 MiB cap. It sends image data, never retrieves a supplied URL/path or grants source access. JSON-object mode; missing fields remain whatever the validated model actually returned, including null.
- `requestTextProposal(input, context)`: prompt/version IDs and a synchronous Zod object schema. The adapter derives strict JSON Schema from that supplied schema; root fields must all be required with additionalProperties=false. Local schema validation still runs on the received object. Tests use A's actual categorySuggestionSchema; no competing category/document schema is defined.
- `requestToolConversation(input, context)`: bounded conversation and selected read-only tool names/descriptions. Parameters come from A's assistantToolSchemas. Returns raw final content or normalized tool-call IDs/name/argument strings as unknown data, after protocol and canonical argument validation. It never executes a tool, checks database ownership, follows URLs or implements an assistant loop. C2 must independently validate/re-scope calls at execution and validate final facts/citations.

The current user explicitly requested public provider-interface tests with an injected scripted provider, fake clock, and observable retry/failure behavior. The tests cross these three public operations with the real installed SDK and replace only external fetch/time/account-budget/telemetry capabilities. A prior interface-adoption entry is not fabricated; C1 publishes this concrete seam for A/C2 review before dependent wiring.

Dependencies: lazy `environment()` getter, optional external `fetch`, clock (`now`, cancellable `setTimer`) and nonblocking `onTelemetry`. Context requires a UUID request ID, absolute epoch-millisecond `deadlineAtMs`, optional AbortSignal and optional synchronous account-budget `take(): boolean`. The adapter always enforces its own two-attempt cap even when no account allowance is supplied. Budget denial and unavailable/non-boolean allowance are distinct failures. This hook is not durable reservation/cache and does not coordinate the organization's quota by itself.

Every operation resolves to `ProviderResult`:

- Success: `{ok:true, output:unknown, metadata}`. A feature operation must parse/map the unknown result to its adopted outcome; this is not an accepted document/category/match or a public API route response.
- Failure: `{ok:false, error:{code,reason,message,retryable,retryAfterMs}, metadata}`. `code` uses A's existing ApiErrorCode: invalid C input -> INVALID_INPUT; provider/config/cancellation/deadline/budget failures -> UNAVAILABLE. Provider authentication failure is not a Clerk UNAUTHENTICATED error. The reason codes are C-local diagnostics, not additions to A's shared enum. Raw exceptions/bodies/abort reasons are never returned.

Metadata contains only validated request/version IDs, fixed mode/model/provider version, measured wall duration, attempts, safe provider request IDs and bounded numerical token usage. It excludes source IDs/URLs, prompts, images, tool arguments, records and secrets. There is no default console logging. Telemetry receives a copy, and a logger exception does not alter the outcome. Response data and domain validation remain separate from safe telemetry.

## Configuration and supported modes

Configuration is read lazily for each operation; imports/factory creation do not inspect environment or infer. Required server-only variables: GROQ_API_KEY, GROQ_VISION_MODEL and GROQ_TEXT_MODEL. Missing/invalid values fail safely before a request; no default model/provider switch. This implementation permits only the step3 verified pair: qwen/qwen3.8-27b for image JSON-object mode and openai/gpt-oss-20b for strict text schema / separate local-tool mode. Qwen is preview; future model changes need a capability/config update.

Versions are explicit prompt/schema IDs ending in `-v` plus a positive integer, such as extraction-v1. Provider version is groq-provider-v1. All requests are non-streaming, temperature0, at most2048 output tokens for image/text and1024 for tool turns. No strict-schema response format is attached to tool requests. Tool parameters come from the installed A schema. Three modes cannot be combined by caller-controlled arbitrary request options.

Limits: A's2 MiB image guard; textual input/schema/tool context cap32000 characters with space reserved for the fixed repair notice; at most16 messages including repair and4 read-only tool definitions/calls; output content cap32000 characters. These are C guards, not measured maximum OCR quality/tokenization or new accepted hosting limits. Caller must supply its host-compatible absolute deadline; the adapter does not guess a cloud route allowance. Keys/model settings are not exposed through NEXT_PUBLIC or next.config. The Groq SDK URL is fixed, SDK logging is off and browser execution is disabled. Gemini uses fixed-origin REST with `store:false`, stateless bounded continuation state and a server-only key header; the browser cannot select or call either adapter directly.

## Retry/deadline behavior

- One retry owner: C. Groq SDK1.6.0 defaults to two retries; both constructor and per-request options explicitly set maxRetries0. No repair/transport path can exceed two actual requests per operation.
- Per-attempt timeout is min(20000ms, remaining outer time). One operation timer includes all requests, validation and backoff. Cancellation and the deadline race the SDK request, so they do not wait for an unbounded successful response. Timers/listeners are disposed. Cancellation does not pretend to undo prior persistence.
- Network errors,408,5xx and attempt timeouts can retry once while time/allowance remains.401/403, ordinary400,404,422 and invalid configuration/request are terminal. Known Groq JSON/tool generation-error codes and malformed/incomplete/schema-invalid output may use the one remaining attempt for a fixed, generic format repair, without copying raw failed output/errors or reserved labels into the prompt. A transport retry followed by malformed output cannot get a third attempt.
- 429 uses validated retry-after seconds/date, retry-after-ms or conservative reset-duration guidance. Missing guidance defers immediately. Reset beyond remaining outer time returns provider_rate_limited with safe retryAfterMs without sleeping past the deadline. Other transient backoff is250ms; no SDK/application retry multiplication or deadline reset.
- No Durable cache, upload pipeline, extraction normalization, category/match engine, financial calculation, tool execution, database call or UI flow is implemented here. Those belong to later steps; domain meanings stay in A's shared contracts.
