### Step 6 — OCR orchestration and durable publication

**Files:** extraction service and the A1-adopted route; proposed `POST /api/documents/{id}/extraction`. **Task:** BA-02. **Needs:** A1 reservation/cache/publication RPCs and C1 adapter.

1. Authenticate/origin-check and resolve document/source before cache/provider work. Reject supplied URLs/paths/ownership.
2. Atomically reserve A1's versioned identity: workspace/source hash plus C's model/prompt/schema/preprocessing versions and required document version. Distinguish miss, in-progress, cached completion and cache outage.
3. Download private bytes with the session-bound Storage client from verified source metadata; apply agreed MIME/size/dimension guards. Do not call the app's own source HTTP endpoint or fetch arbitrary URLs.
4. Invoke C1 with deadline/signal and minimal authorized context. C has no database mutation capability.
5. Validate proposals: null/uncertainty, normalized exact money/date/currency, field references and safe versions/provenance.
6. Publish through the version-checked RPC. Results arriving after user correction must conflict/be nonactionable under A1's policy; they cannot overwrite reviewed fields.
7. Persist safe failure/operation state while preserving source/books. Respect C's retry owner; no outer loop or fire-and-forget work after response.
8. Successful repeats reuse durable output; expired reservations follow A1's recovery policy.

**Acceptance:** cache avoids repeated inference; simultaneous calls share a reservation; timeout/429/malformed/cancellation preserve books; unknown total stays null; accepted corrections survive reruns; stale publication fails. Label mocked and live evidence separately.

### Step 7 — Explicit document review

**Files:** review service and `PATCH /api/documents/{id}`. **Task:** BA-02. **Needs:** A1 atomic review command.

1. Parse adopted accept/correct/reject action, expected version, reviewed fields and retry key where defined.

3. Use the atomic RPC for original/extracted/corrected separation, actor/timestamp/history and optimistic versions.
4. Preserve adopted no-op/retry behavior. Same key with changed payload and stale saves conflict promptly.
5. If fields on an already matched document change, use A1's agreed allocation invalidation/review behavior; never directly edit match tables.

**Acceptance:** originals/history survive reload and correction/rejection; stale 409; uncertain acceptance blocked; no cash creation; accepted-match consistency follows A1's atomic operation.

### Step 8 — Category proposal wrappers/listing

4. Assign IDs/ownership on the server; persist atomically with snapshots/retry/supersession guards.
5. List scoped stored proposals/statuses/reasons/references; no unaccepted category enters the transaction record.

**Acceptance:** valid suggestions reload; ambiguity abstains; forged IDs/invalid labels fail; accepted decisions/totals survive reruns; partial failures follow the adopted policy; no automatic acceptance.

**Acceptance:** equal amounts remain ambiguous when warranted; incompatibility stays unresolved; stale/allocation conflicts fail; accepted matches survive reruns; foreign IDs fail; proposal generation changes no allocation/cash.
